# 3D

## Transforms — get these right and most 3D bugs disappear

- **Right-handed, +Y up, forward is -Z.** `-global_basis.z` is the direction a node faces. `Vector3.FORWARD` = `(0, 0, -1)`.
- `Transform3D` = `basis` (rotation + scale, 3 axis vectors) + `origin` (position). `global_transform.basis.x/y/z` are the node's right/up/back axes in world space.
- Rotate with `rotate_y(angle)`, `rotate_object_local(axis, angle)`, or build a `Basis` — don't accumulate `rotation_degrees.x += ...` on multiple axes (Euler order problems / gimbal lock).
- `look_at(target, Vector3.UP)` fails (error, NaN basis) when the direction is parallel to `up` — guard or pass a different up for vertical aims.
- Interpolating rotation: `basis.slerp()` or `Quaternion.slerp()`, never lerp Euler angles across the ±180° wrap.
- Non-uniform scale on a `CollisionShape3D` or physics body breaks collision. Scale the shape's size/radius instead, and keep physics body scale at 1.
- Imported model faces +Z? Fix in the import settings (root rotation) or rotate a child `Model` node 180° — never compensate in movement code.

## Third-person controller

```gdscript
class_name Player3D
extends CharacterBody3D

@export var move_speed: float = 6.0
@export var accel: float = 30.0
@export var air_accel: float = 8.0
@export var jump_velocity: float = 5.5
@export var turn_sharpness: float = 12.0
@export var mouse_sensitivity: float = 0.002   # rad per pixel
@export var pitch_limit_deg: float = 70.0

@onready var _yaw: Node3D = %CameraYaw        # rotates around Y
@onready var _pitch: Node3D = %CameraPitch    # child of yaw, rotates around X
@onready var _model: Node3D = %Model


func _ready() -> void:
	Input.mouse_mode = Input.MOUSE_MODE_CAPTURED


func _unhandled_input(event: InputEvent) -> void:
	var motion := event as InputEventMouseMotion
	if motion and Input.mouse_mode == Input.MOUSE_MODE_CAPTURED:
		_yaw.rotate_y(-motion.relative.x * mouse_sensitivity)
		_pitch.rotation.x = clampf(
			_pitch.rotation.x - motion.relative.y * mouse_sensitivity,
			deg_to_rad(-pitch_limit_deg), deg_to_rad(pitch_limit_deg))
	elif event.is_action_pressed(&"ui_cancel"):
		Input.mouse_mode = Input.MOUSE_MODE_VISIBLE


func _physics_process(delta: float) -> void:
	if not is_on_floor():
		velocity += get_gravity() * delta           # 4.3+: respects Area3D gravity overrides
	elif Input.is_action_just_pressed(&"jump"):
		velocity.y = jump_velocity

	# Camera-relative input: flatten the yaw basis so looking down doesn't slow movement.
	var input := Input.get_vector(&"move_left", &"move_right", &"move_forward", &"move_back")
	var cam_basis := _yaw.global_basis
	var dir := (cam_basis.x * input.x + cam_basis.z * input.y)
	dir.y = 0.0
	dir = dir.normalized() * input.length()          # keep analog magnitude

	var rate := accel if is_on_floor() else air_accel
	var horizontal := Vector3(velocity.x, 0.0, velocity.z).move_toward(dir * move_speed, rate * delta)
	velocity.x = horizontal.x
	velocity.z = horizontal.z

	if dir.length_squared() > 0.001:
		var target_yaw := atan2(-dir.x, -dir.z)      # model faces -Z
		_model.rotation.y = lerp_angle(_model.rotation.y, target_yaw, 1.0 - exp(-turn_sharpness * delta))

	move_and_slide()
```

Node tree:

```
Player3D (CharacterBody3D)
├── Collision (CollisionShape3D, CapsuleShape3D)
├── Model (Node3D) ── imported character scene
└── CameraYaw (Node3D, top_level = false)
    └── CameraPitch (Node3D)
        └── SpringArm3D (spring_length = 4, collision mask = world only, excludes the player)
            └── Camera3D
```

- `SpringArm3D` keeps the camera out of walls; set its mask to world geometry and add the player body to its exclusions (or use a separate layer).
- If the camera jitters, it's a tick mismatch: enable physics interpolation (4.4+ for 3D). Otherwise smooth the camera in `_process` using the interpolated position.
- First-person: put the Camera3D directly under the pitch node at eye height; rotate the body with yaw instead of a separate yaw node.

## Importing models

- Prefer **glTF 2.0 (`.glb`)**. `.blend` imports directly if Blender's path is configured in Editor Settings — convenient, but CI/export machines then need Blender too. FBX imports via the built-in ufbx importer.
- Configure per-file in the Import dock or the Advanced Import Settings: root type, root scale, animation looping, physics generation, materials extraction.
- Name suffixes in the DCC tool generate collision automatically: `-col` (mesh + static collision), `-colonly` (collision only), `-convcol`, `-convcolonly`, `-rigid`, `-navmesh`, `-noimp`, `-loop` for animations.
- Don't edit the imported scene directly — changes are lost on reimport. Create an **inherited scene** or instance the model inside your own scene (`Enemy.tscn` → `Model` child).
- Extract materials to `.tres` files if you want to edit them in Godot and keep edits through reimports.
- Retargeting humanoid animations: use the Skeleton3D retargeting with a `SkeletonProfileHumanoid` BoneMap on import.

## Renderer and lighting

| Feature | Forward+ | Mobile | Compatibility |
|---|---|---|---|
| SDFGI (real-time GI, large open worlds) | ✓ | – | – |
| VoxelGI (real-time GI, bounded areas) | ✓ | – | – |
| LightmapGI (baked) | ✓ | ✓ | ✓ (4.3+) |
| Volumetric fog | ✓ | – | – |
| SSAO/SSIL/SSR | ✓ | – | – |
| Many dynamic lights | ✓ (clustered) | limited per mesh | limited |
| Web export | – | – | ✓ |

Defaults:
- One `DirectionalLight3D` with shadows + `WorldEnvironment` (sky, tonemap AgX/Filmic, glow) is the baseline outdoor setup.
- Static indoor lighting → `LightmapGI` (needs UV2; enable "Generate Lightmap UV2" or "Light Baking: Static Lightmaps" on import).
- Shadow cost scales with shadow-casting lights × shadow-casting meshes. Turn off `shadow_enabled` on minor lights; turn off `cast_shadow` on small props.
- `ReflectionProbe` for local reflections; don't rely on SSR on Mobile/Compatibility.
- Test on the target renderer early: switching renderer late changes the look substantially.

## GridMap

3D tile-based levels from a `MeshLibrary` (export one from a scene of meshes with collision). Good for block-based or modular dungeon levels. For modular kits with complex pieces, placing instanced scenes directly with snapping is often more flexible.

## Level of detail and culling

- Automatic mesh LOD is generated on import (`Generate LODs`); tune `lod_bias` per instance if needed.
- `visibility_range_begin/end` on GeometryInstance3D for manual HLOD and fading distant props.
- `OccluderInstance3D` + baked occluders (enable `rendering/occlusion_culling/use_occlusion_culling`) for dense interiors and cities; it costs CPU, so skip it for open terrain.
- `VisibleOnScreenNotifier3D` / `VisibleOnScreenEnabler3D` to stop processing offscreen AI.

## Large worlds

- Beyond ~8 km from the origin, single-precision floats jitter. Options: keep playable areas small and stream levels; origin shifting (periodically move the world so the player is near 0); or a double-precision engine build (`precision=double`, custom build, applies to GDExtensions too).
- Stream chunks with `ResourceLoader.load_threaded_request` and add them when ready.

## Common 3D math

```gdscript
# Direction and distance
var to_target := target.global_position - global_position
var dist := to_target.length()
var dir := to_target / dist if dist > 0.0 else Vector3.ZERO

# Is target in front, within a 60° cone?
var forward := -global_basis.z
var in_cone := forward.dot(dir) > cos(deg_to_rad(30.0))

# Flatten to ground plane
var flat := Vector3(dir.x, 0.0, dir.z).normalized()

# Smoothly face a direction around Y only
var target_yaw := atan2(-flat.x, -flat.z)
rotation.y = lerp_angle(rotation.y, target_yaw, 1.0 - exp(-10.0 * delta))

# Project velocity onto the ground normal (slopes)
var on_plane := velocity.slide(get_floor_normal())
```
